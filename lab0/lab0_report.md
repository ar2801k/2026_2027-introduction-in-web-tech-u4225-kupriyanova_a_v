# Лабораторная работа №0

## Цель работы

Настроить Git и GitHub для дальнейшего выполнения лабораторных работ по курсу «Введение в веб технологии».

## Ход работы

### 1. Проверка Git

Была проверена установленная версия Git:

```bash
git --version
```

Результат:

```text
git version 2.53.0.windows.2
```

### 2. Настройка SSH

Для GitHub-аккаунта `ar2801k` был создан отдельный SSH-ключ:

```bash
ssh-keygen -t ed25519 -C "ar2801k" -f "%USERPROFILE%\.ssh\id_ed25519_ar2801k"
```

После этого публичный SSH-ключ был добавлен в настройки GitHub.

Для проверки подключения была выполнена команда:

```bash
ssh -T -i "%USERPROFILE%\.ssh\id_ed25519_ar2801k" -o IdentitiesOnly=yes git@github.com
```

Результат:

```text
Hi ar2801k! You've successfully authenticated, but GitHub does not provide shell access.
```

SSH-подключение к GitHub было успешно настроено.

### 3. Создание репозитория

Был создан публичный GitHub-репозиторий:

```text
2026_2027-introduction-in-web-tech-u4225-kupriyanova_a_v
```

После создания репозиторий был клонирован на локальный компьютер.

### 4. Настройка структуры репозитория

В корне репозитория были созданы следующие файлы:

- `.gitignore`
- `README.md`
- `LICENSE`
- `CONTRIBUTING.md`

Также были созданы папки для лабораторных работ:

- `lab0`
- `lab1`
- `lab2`
- `lab3`

Для каждой лабораторной работы предусмотрен отдельный файл отчёта в формате Markdown.

### 5. Работа с ветками

Для работы с репозиторием были созданы две ветки:

```text
main
develop
```

Ветка `main` используется как основная, а ветка `develop` — для внесения изменений перед их объединением с основной веткой.

### 6. Создание CONTRIBUTING.md

В ветке `develop` был создан файл `CONTRIBUTING.md`.

В нём были описаны основные правила работы с репозиторием:

- использование ветки `main` как основной;
- выполнение изменений в ветке `develop`;
- создание отдельных коммитов;
- объединение изменений через Pull Request.

После создания файла изменения были добавлены в Git, зафиксированы коммитом и отправлены в удалённый репозиторий.

### 7. Pull Request

Для переноса изменений из ветки `develop` в ветку `main` был создан Pull Request:

```text
develop -> main
```

После проверки изменений Pull Request был успешно объединён с основной веткой `main`.

### 8. Синхронизация веток

После объединения Pull Request локальная ветка `main` была синхронизирована с удалённым репозиторием.

Для проверки состояния репозитория была выполнена команда:

```bash
git status
```

Результат:

```text
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
```

Также была выполнена проверка локальных веток:

```bash
git branch
```

Результат:

```text
develop
* main
```

Это подтверждает, что основная ветка `main` синхронизирована с GitHub, а ветка `develop` сохранена для дальнейшей работы.

В результате репозиторий подготовлен для выполнения следующих лабораторных работ по курсу «Введение в веб технологии».
